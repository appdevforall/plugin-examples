AI Assistant — Agent Guide

The Agent tab is a chat assistant that can read, search, and edit your project through an approval-gated tool loop. Inference is served by the companion AI Core plugin, so install AI Core first.

Where the settings live

The backend, the model and your Gemini API key are all configured on one screen, reached from Preferences → Configuration → Agent. The same screen opens from the Agent tab's overflow menu (Settings), so you do not have to leave the chat to change something. Every setting saves as you change it.

Choosing a backend

  • Local (on-device) — runs a .gguf model via llama.cpp. Open Preferences → Configuration → Agent and pick a model file from your Downloads folder. Nothing leaves the device.
  • Gemini (cloud) — enter a Gemini API key on the same screen; see Getting a Gemini API key below. Prompts and any file contents the agent reads are sent to Google over HTTPS.

What the agent can do

  • Read and search files within the current project.
  • Create and update files (asks for approval before writing).
  • Edit part of a file — the agent proposes a find/replace change, and the approval dialog shows you the exact before/after before anything is written. You can Accept it, Decline it, or choose Correct to tell the agent what to change and let it try again. When the file is open in the editor, the change is applied to the buffer, so Ctrl+Z undoes it and your unsaved work is preserved.
  • Trigger a Gradle sync and read build output.
  • Add dependencies and generate code from templates.
File tools are confined to the project root: paths that resolve outside it are rejected, so the model cannot read or overwrite arbitrary files on the device.

Attaching context files

  • Tap the attach button beside the prompt to pick files whose contents are sent with your next message.
  • The picker is rooted at the project you have open and cannot browse above it. With no project open it declines to open at all.
  • Toggle All selects every file in the folder you are viewing; Add Selected attaches them as chips above the prompt.
  • On the Gemini backend, attached file contents leave the device.

Getting a Gemini API key

You do not need the Google Cloud console. Keys are created at aistudio.google.com/apikey, and Google AI Studio sets up the underlying Cloud project for you the first time you accept its terms.

  1. On the Agent settings screen with the Gemini backend selected, tap Get API Key. Your normal browser opens at AI Studio.
  2. Sign in with your Google account in the browser and tap Create API key. This plugin never sees your Google password.
  3. Copy the key Google shows you, return to the IDE and paste it into the Gemini API Key field (long-press the field, then Paste).
  4. Tap Save Key. The key is checked with Google immediately.

What Save reports:

  • Verified — your API key works — Google accepted the key and it has been stored.
  • Key accepted, Google is rate-limiting — the key is valid and stored; the quota is busy right now, not the credential.
  • Invalid API key — Google refused it, so nothing is saved. Check what you pasted and try again. Keys are long, single-line, and contain no spaces.
  • Couldn't reach Google / Couldn't check this key — the check itself failed (no network, or the AI Core plugin is disabled or out of date), so you are asked whether to keep the key anyway. Kept this way it is stored but not confirmed, and the status line says so.

If no browser is installed, the AI Studio link is copied to the clipboard so you can open it on another device and type the key in by hand.

AI Studio isn't available in every country. If you can't create a key, the Local backend needs no account at all — pick a .gguf chat model and everything runs on the device.

Free tier and your data

Gemini has a free tier that is enough to use this plugin. Be aware that on the free tier Google may use prompts and responses to improve its products; the paid tier does not. Because the agent sends your prompts, project context and the contents of files it reads, that applies to your code too. This has always been true of the Gemini backend — it is written down here so it isn't a surprise. The Local backend sends nothing anywhere.

Your Gemini API key

The key is encrypted with AES/GCM under a hardware-backed Android Keystore secret, and only the ciphertext is written to the plugin's private storage — a copied preferences file is useless without this device's Keystore. Clear it any time from Preferences → Configuration → Agent. If the Keystore entry is ever lost — clearing the app's data, for example — the stored key can no longer be read and will need to be entered again; tapping Edit tells you when that has happened.

Reading the conversation

  • Retry appears on a message whose reply failed, and re-sends the same prompt with the same attached files rather than adding a new one.
  • Open AI Settings appears instead when the agent has not been configured yet — no local model chosen, or no Gemini key saved. It opens the Agent settings screen directly.
  • System log rows are collapsed records of the agent's internal steps: tools run, files touched, backend errors. Tap the header to expand one. They are saved with the session but are not sent to the model.
  • Long-press a message to copy its text, or to edit and re-send one of your own.

Troubleshooting

  • "No model configured" — select a .gguf file (Local) or set an API key (Gemini) under Preferences → Configuration → Agent.
  • Gemini errors — check the API key, network connection, and quota. Re-tapping Save on the key re-runs the live check and tells you which of the three it is.
  • "Invalid API key" — the key was not stored. Make sure you copied the key itself from AI Studio and not the page's URL.
  • Agent tab missing — confirm both AI Core and AI Assistant are installed and the IDE was restarted.
