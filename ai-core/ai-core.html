AI Core Plugin

Executive overview

AI Core is the shared large-language-model (LLM) inference router for CodeOnTheGo's AI plugins. It is a headless plugin — it has no screens of its own. It registers a single inference service that the other AI plugins (AI Assistant, Code Suggestions, Speech to Text, and Vector Search) call at runtime.

AI Core provides no models itself. Inference is supplied by separate backend plugins — AI Local Backend for on-device models, AI Gemini Backend for Google's API — which register with AI Core when they activate. Install AI Core and at least one backend; without a backend, requests fail with "Backend not found". Install order does not matter.

Core functionality

  • Registers a shared inference service so every AI plugin talks to one router instead of bundling its own engine.
  • Dynamic backend registry — backends are added and removed at runtime by their own plugins. AI Core hardcodes no backend list, so a new provider is a new plugin, not a change here.
  • Request routing — resolves the backend selected in AI Assistant's settings, and falls back to any available backend when the selected one is not installed or not configured.
  • Capability negotiation — uses a backend's tool-calling, multi-turn and cancellation support where it declares it, and degrades cleanly where it does not.
  • Text completion, chat with history, and streaming responses, plus a single cancellation path so Stop reaches whichever backend is running.

Technical architecture

ComponentRole
AiCorePluginPlugin entry point. Publishes the inference service on activation and withdraws it on deactivation. Owns no backend.
LlmInferenceServiceImplThe service exposed via SharedServices. Holds the backend registry and routes each request to the resolved backend.
AiBackendMaps the backend setting stored by AI Assistant onto a registered backend id, translating the two legacy values that predate the id-as-setting convention.
ConfigFieldSpecSupplied by each backend via getConfigSpecs(), describing the credentials or files it needs so settings UI can be drawn without knowing the provider's API.

AI Core declares no Android permissions: it opens no connections, reads no files, and loads no native code. Those belong to the backend plugin that serves a given request.

Usage

  1. Install AI Core via the Plugin Manager.
  2. Install at least one backend: AI Local Backend, AI Gemini Backend, or both. Restart the IDE.
  3. Install one or more consumer plugins (e.g. AI Assistant).
  4. Open AI Assistant → AI Settings to choose a backend and configure it — select a local .gguf model file, or enter a Gemini API key. AI Core has no settings screen of its own; it reads this configuration at request time.
Installing both backends is supported and useful: pick the local one for privacy and the Gemini one for capability, and switch between them in AI Settings without reinstalling anything.

Key benefits

  • One router, many plugins — a single inference service shared across all AI features, so backend and model choice are configured once.
  • Install only what you need — a device that only ever uses the cloud backend need not carry an 8 MB native library, and one that never goes online need not carry a network-capable plugin at all.
  • Least privilege — network access, filesystem access and native code are declared by the specific backend that needs them, so what a user grants matches what they installed.
  • Extensible — adding a provider means writing a new backend plugin; neither AI Core nor any consumer plugin changes.
