AI Core Plugin

Executive overview

AI Core is two things in one plugin: the Agent chat you code with, and the shared large-language-model (LLM) inference router that every other AI plugin in CodeOnTheGo calls at runtime. It contributes an Agent tab to the editor and an Agent row to Preferences → Configuration, and it registers a single inference service that Code Suggestions, Speech to Text and Vector Search share.

AI Core provides no models itself. Inference is supplied by separate backend plugins — AI Agent Local for on-device models, AI Agent Gemini for Google's API — which register with AI Core when they activate. Install AI Core and at least one backend; without a backend, requests fail with "Backend not found". Install order does not matter.

Core functionality

  • Agent chat — a conversational editor tab that can read and edit project files, add dependencies, run a Gradle sync and launch the app, with every file-changing action gated behind an approval dialog.
  • Agent settings — one screen to pick the backend and configure it; each backend contributes its own portion of that screen.
  • Registers a shared inference service so every AI plugin talks to one router instead of bundling its own engine.
  • Dynamic backend registry — backends are added and removed at runtime by their own plugins. AI Core hardcodes no backend list, so a new provider is a new plugin, not a change here.
  • Request routing — resolves the backend selected in Agent settings, and falls back to any available backend when the selected one is not installed or not configured.
  • Capability negotiation — uses a backend's tool-calling, multi-turn and cancellation support where it declares it, and degrades cleanly where it does not.
  • Text completion, chat with history, and streaming responses, plus a single cancellation path so Stop reaches whichever backend is running.

Technical architecture

ComponentRole
AiCorePluginPlugin entry point. Contributes the Agent tab and the Agent settings row, publishes the inference service on activation and withdraws it on deactivation. Owns no backend.
LlmInferenceServiceImplThe service exposed via SharedServices. Holds the backend registry and routes each request to the resolved backend.
ChatFragment / ChatViewModelThe Agent tab: message history, streaming output, the Stop control, and the approval dialog shown before any file is written.
Tool handlers + PathGuardThe actions the agent may take. Every path is canonicalised and confined to the project root, and generated trees, .git/, build configuration and keystores are refused outright.
AiBackendMaps the backend setting stored in Agent settings onto a registered backend id, translating the two legacy values that predate the id-as-setting convention.
ConfigurableBackendImplemented by a backend that draws its own settings screen, so the credentials or files it needs are collected without AI Core knowing the provider's API.

AI Core declares filesystem.read, filesystem.write, system.commands and project.structure — the agent reads and edits files in the open project, triggers Gradle sync and run through the IDE's own build service, and inspects the project's module structure. It declares no network access and loads no native code: those belong to the backend plugin that serves a given request, so a device using only the local backend never grants a network-capable AI plugin.

Usage

  1. Install AI Core via the Plugin Manager.
  2. Install at least one backend: AI Agent Local, AI Agent Gemini, or both. Restart the IDE.
  3. Open Preferences → Configuration → Agent to choose a backend and configure it — select a local .gguf model file, or enter a Gemini API key. The same screen is reachable from the Agent tab.
  4. Open a project and switch to the Agent tab to start chatting. Any action that changes a file asks for your approval first.
Installing both backends is supported and useful: pick the local one for privacy and the Gemini one for capability, and switch between them in Agent settings without reinstalling anything.

Key benefits

  • One router, many plugins — a single inference service shared across all AI features, so backend and model choice are configured once.
  • Install only what you need — a device that only ever uses the cloud backend need not carry an 8 MB native library, and one that never goes online need not carry a network-capable plugin at all.
  • Least privilege — network access, filesystem access and native code are declared by the specific backend that needs them, so what a user grants matches what they installed.
  • Extensible — adding a provider means writing a new backend plugin; neither AI Core nor any consumer plugin changes.
