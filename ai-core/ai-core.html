AI Core Plugin

Executive overview

AI Core is the shared large-language-model (LLM) inference backend for CodeOnTheGo's AI plugins. It is a headless plugin — it has no screens of its own. Instead it registers a single inference service that the other AI plugins (AI Assistant, Code Suggestions, Speech to Text, and Vector Search) call at runtime.

Install AI Core first, then any of the plugins that depend on it. Without AI Core installed and activated, those plugins have no LLM backend and will report that the inference service is unavailable.

Core functionality

  • Registers a shared inference service so every AI plugin talks to one backend instead of bundling its own.
  • Local (on-device) backend — runs a .gguf model through a bundled, prebuilt llama.cpp library. Prompts and code never leave the device.
  • Gemini (cloud) backend — calls Google's Gemini API over HTTPS using a user-supplied API key. Supports live model listing so retired model names are never offered.
  • Model safety checks — inspects a selected .gguf header and refuses embedding-only models for chat, with a clear error instead of a native crash.
  • Text completion, chat with history, and streaming responses. (Native Gemini function calling is not yet wired up; tool-enabled requests fall back to plain streaming.)

Technical architecture

ComponentRole
AiCorePluginPlugin entry point. Registers the inference service and both backends on activation; unregisters and frees resources on deactivation/dispose.
LlmInferenceServiceImplThe service exposed via SharedServices. Routes each request to the selected backend.
LocalLlmBackendOn-device inference over the prebuilt llama.cpp AAR. Resolves the selected model (including SAF content:// URIs) to a real file path and manages loading.
GeminiBackendCloud inference via direct calls to the Gemini REST API over HttpURLConnection (no third-party SDK). Sends the API key as an x-goog-api-key header, never in a URL.
GgufModelInspectorMinimal GGUF header reader that classifies a model as chat- or embedding-only.

The native library is committed prebuilt (four ABIs: arm64-v8a, armeabi-v7a, x86, x86_64), so a normal build needs no NDK, CMake, or the llama.cpp submodule.

Usage

  1. Install AI Core via the Plugin Manager, then restart the IDE.
  2. Install one or more consumer plugins (e.g. AI Assistant).
  3. Open AI Assistant → AI Settings to choose a backend and configure it — select a local .gguf model file, or enter a Gemini API key. AI Core has no settings screen of its own; it reads this configuration at request time.
Embedding-only .gguf files cannot serve chat requests. If one is selected for chat, the request is rejected with a clear message instead of crashing the IDE.

Key benefits

  • One backend, many plugins — a single inference service shared across all AI features, so backend and model choice are configured once.
  • On-device privacy option — the local backend keeps prompts and code entirely on the device.
  • Cloud power option — the Gemini backend adds a high-capability model when connectivity and an API key are available.
  • Crash-resistant — model classification and header bounds-checking turn would-be native crashes into recoverable, user-visible errors.
  • Reproducible builds — no NDK required; the native library ships prebuilt.
